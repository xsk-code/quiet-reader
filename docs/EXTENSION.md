# 浏览器插件：一键导入

在 Chrome 或 Edge 里打开任意文章，点一下工具栏图标，拾页就会在本机排队导入，并自动打开阅读页。也可以右键页面或链接，或按 `Alt+Shift+R`。

插件只把**当前页面（或右键链接）的网址**交给本机服务；不读取正文、Cookie、登录状态或浏览记录。

## 准备

- 拾页已在默认地址 <http://127.0.0.1:4317> 运行（`npm start`）。
- Chrome / Edge 103 或更新版本。Safari 不支持 Chrome 扩展，见文末替代方案。

## 安装

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择项目根目录下的 `extension/` 目录。
4. 在工具栏的扩展菜单里把“拾页 · 一键导入”固定出来。

不同用户各自加载自己仓库里的 `extension/` 目录即可，不需要修改扩展 ID，也不需要和本机服务配对密钥；服务端只按 `chrome-extension://` 来源放行导入接口。

更新项目代码后，在扩展卡片上点刷新按钮，并重启 `npm start`，再刷新已打开的拾页标签页。

## 使用

1. 在文章页点扩展图标。插件把网址 `POST` 到本机 `/api/import`。
2. 服务返回任务编号后，插件打开（或复用）拾页标签页：`/?job=<任务编号>`。
3. 页面显示抓取、分段翻译的进度；完成后自动进入译文阅读。

右键菜单：

- “用拾页阅读这一页”：导入当前页面。
- “用拾页阅读这个链接”：导入链接目标，不必先打开它。

快捷键 `Alt+Shift+R`（macOS 为 Option+Shift+R）可在 `chrome://extensions/shortcuts` 改成其他组合。

## 没有直接导入时

工具栏图标显示 `!` 时，插件会把网址填进拾页的 `/?pending=<网址>` 页面，并停在导入栏。确认后点“开始阅读”即可，网址不会丢失。常见原因：

- 拾页没有启动，或没有监听默认端口 4317。
- 模型接入尚未配置，服务返回 `MODEL_NOT_CONFIGURED`。
- 浏览器拦截了扩展的本地请求；此时仍可用上面的确认导入。

登录墙、付费墙和反爬仍由服务端按原有规则抓取，插件不会绕过，也不会借用浏览器登录态。抓取失败时阅读页仍会给出“打开原文”和“粘贴正文”。

## 权限与隐私

| 权限 | 用途 |
| --- | --- |
| `activeTab` | 仅在点击图标、右键菜单或快捷键时读取当前标签页网址 |
| `contextMenus` | 添加两个右键菜单项 |
| `http://127.0.0.1:4317/*`、`http://localhost:4317/*` | 把导入请求发给本机拾页 |

- 没有内容脚本，不注入页面，不读取正文、Cookie、localStorage 或账号信息。
- 插件没有远程代码、统计或第三方请求；所有请求只到本机。
- 服务端只对 `chrome-extension://` 来源开放 `POST /api/import`，其他接口继续拒绝跨站请求。
- 本机已安装的其他扩展理论上也能触发一次导入，因此会消耗一次抓取和模型调用，并向文章库写入一篇新文章；它不能读取已有文章、配置或密钥。不用时移除本插件即可。

## 打包与分发

```sh
npm run extension:zip
```

生成 `release/quiet-reader-extension-<版本>.zip`，同时输出 SHA-256。压缩包只包含 `manifest.json`、service worker、`lib.mjs` 和 manifest 引用的图标，不含 README、测试或源码；条目使用固定时间戳，同样内容重复打包会得到相同哈希。

分发时可以：

- 让使用者解压后按上面的步骤“加载已解压”，仍然需要先启动本机拾页；
- 或把 zip 直接上传 Chrome Web Store / Edge Add-ons。扩展依赖本机服务，商店说明里要写清启动方式，并准备隐私说明和审核材料；
- 把 zip 作为 GitHub Release 附件，附上输出的 SHA-256；`release/` 已被忽略，不会进入源码仓库。

`extension/manifest.json` 的版本必须与 `package.json` 一致。`npm test` 会检查这一点，`npm run extension:zip` 在版本不一致时也会拒绝打包。

## 限制

- 只支持默认地址 `http://127.0.0.1:4317`。用 `PORT` 改端口时，需要同步修改 `extension/lib.mjs` 的地址和 `extension/manifest.json` 的 `host_permissions`，再重新加载扩展；不推荐。
- 插件不处理站内跳转或无限滚动；它导入的是当前标签页的地址。
- Safari 无法直接加载这个目录。可以在 Safari 里新建书签，地址填下面的代码，在文章页点书签后确认一次：

  ```js
  javascript:window.open('http://127.0.0.1:4317/?pending='+encodeURIComponent(location.href),'_blank')
  ```

  少数站点会禁止 `javascript:` 书签；这种情况下仍可复制正文后粘贴。

## 排错

| 现象 | 处理 |
| --- | --- |
| 点图标没有反应 | 在 `chrome://extensions` 查看扩展卡片上的“服务工作进程”错误；重新加载扩展 |
| 图标显示 `!` | 确认 `npm start` 正在运行，且地址是 <http://127.0.0.1:4317> |
| 打开了拾页但没有文章 | 查看页面上的任务提示；模型未配置时先完成“模型接入” |
| 想导入右键的链接 | 使用“用拾页阅读这个链接”，或先打开链接再点图标 |
| 改了端口后失败 | 扩展只认 4317；恢复默认端口，或同步修改扩展地址并重新加载 |
